# Phase 1 — UI Shell (Upload, Rule Select, ε Slider, Canvas, Verdict) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build build-plan item 01 — the full single-screen UI shell with mock pipeline data, so layout, controls, canvas overlay and verdict card are visually verifiable before Phases 2–4 wire real CV/OCR.

**Architecture:** Vanilla TS + DOM factory functions. A pure `src/mock/demo-drawings.ts` supplies hand-authored demo drawings (ideal + tilted), and the UI runs the already-tested `verify()` engine on them — rule switching and the ε slider genuinely flip Success↔Fail with zero CV/OCR. `src/ui/app.ts` wires state/events; `main.ts` bootstraps.

**Tech Stack:** Vite 8, TypeScript strict, Vitest 4 (mock/pipeline only), oxlint, Prettier. No framework, no Tailwind, no jsdom.

## Global Constraints

- Vanilla TS + Vite SPA only; no framework, no Tailwind, no backend.
- TypeScript strict (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`); no `any`.
- Design tokens only: `var(--color-*)` from `ui-tokens.md`/`styles.css`; no raw hex in components. All numbers in `font-num` + `tabular-nums`.
- UI copy in Russian; exact ТЗ strings are contract — verdict messages come from `verify.ts` unchanged.
- ε default/thresholds from `src/pipeline/constants.ts` (`EPS_DEFAULT = 3.0`); slider bounds 0.5–10, step 0.5 (build-plan 01).
- Windows PowerShell: `pnpm.cmd` exit codes unreliable → run gates as `cmd /c "pnpm <cmd> && echo PASS || echo FAIL"`.
- **Repo rule (.clinerules §4): one commit per feature.** Tasks here do NOT commit individually; everything lands in one `feat(ui): …` commit at Task 5 (tracker/registry/memory included).

## Task 4: App wiring + bootstrap + styles

**Files:** Create `src/ui/app.ts`; Modify `src/main.ts`, `src/styles.css`.

**Interfaces (produced):** `createApp(root: HTMLElement): void` — builds the shell once (topbar + status dot → canvas card → controls card → verdict card), owns `AppState`, and:
- auto-runs the mock verification on load and after every state change (mock compute is free; «Проверить» re-runs on demand — the explicit trigger that matters from Phase 4);
- `update(patch: Partial<AppState>)` → refresh canvas + re-run verdict;
- upload → `URL.createObjectURL(file)` (revokes the previous URL);
- status dot tone: ok (Success) / danger (Fail|Error), `aria-hidden`.

Layout (ui-rules): topbar (title + verdict status dot) → canvas card (upload zone until an image loads) → controls card (rule select, ε slider, «Проверить») → verdict card.
