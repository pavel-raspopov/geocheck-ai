# GeoCheck AI — Продуктовый бриф

## Цель

Построить модуль **GeoCheck AI**: автоматическая проверка соответствия растрового чертежа текстовым геометрическим условиям задачи. Школьный/портфолио проект: чистый код, тесты и аккуратный README важнее масштаба.

Единый источник правды — ТЗ в корне репозитория (`product-brief.md`). Этот файл — его агент-читаемая адаптация.

## KPI (из ТЗ)

- **Accuracy** ≥ 95% на цифровых чертежах.
- **Автоматизация:** полное исключение ручной проверки графической части преподавателем.
- **Быстродействие:** полная обработка одного изображения ≤ 3 секунд на CPU.

## Область (сквозной пайплайн)

1. **Вход:** растровое изображение чертежа + строка геометрического условия (или выбранный тип правила).
2. **Экстракция линий:** поиск всех отрезков с определением их экранных координат (min длина 30 px).
3. **Дедупликация:** кластеризация (разность углов ≤ 5° и евклидово расстояние ≤ 7 px) + слияние кластера по двум самым удалённым точкам.
4. **OCR:** одиночные латинские буквы (A–Z), автоприведение к UPPERCASE, сохранение координат центра.
5. **Сборка графа:** вершина = точка пересечения отфильтрованных отрезков; буква привязывается к ближайшей вершине ≤ 40 px.
6. **Верификация:** проверка геометрических инвариантов (формулы в `architecture.md`), ε по умолчанию 3.0.
7. **Выход:** вердикт «Верно / Ошибка с описанием отклонения».

## Типы правил (математический движок)

- **Перпендикулярность (ABC = 90°):** угол через арккосинус отношения скалярного произведения векторов BA·BC к произведению их длин; отклонение от 90° ≤ ε.
- **Параллельность (AB ∥ CD):** модуль косого произведения |cross(AB, CD)| стремится к 0 (нормализованный угол ≤ ε).
- **Равенство отрезков (AB = CD):** |L_AB − L_CD| ≤ ε px.
- **Принадлежность точки (M ∈ AB):** (AM + MB) − AB ≤ ε px — неравенство треугольника гарантирует, что M лежит строго между A и B.

## Нефункциональные требования и UX

- **Отказоустойчивость:** ненайденная буква → мягкая ошибка `[Status: Error] Точка X не найдена на чертеже` (без падений/KeyError).
- **Быстродействие:** ≤ 3 с на CPU (проверяется на демо-чертеже, Фаза 5).
- **UI:** поле загрузки файла (Drag-and-Drop), выпадающий список правил, ползунок ε.

## Что такое хороший результат (критерии приёмки, ТЗ §5)

- Идеальный прямоугольный треугольник ABC → статус `Success`.
- Угол 84° при ε=3 → `Fail` и текст: «Ошибка: Угол ABC на рисунке равен 84.12°, отклонение составляет 5.88°».
- M на прямой AB, но за точкой B (вне отрезка) → `Fail`.
- `pnpm test` + `pnpm typecheck` + `pnpm build` — зелёные; README честно описывает возможности.
